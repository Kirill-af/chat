# Чат MAX на React

Небольшой веб-чат для отправки и получения текстовых сообщений через [GREEN-API](https://green-api.com/max). Внешний вид ориентирован на [web.max.ru](https://web.max.ru/): список чатов слева, переписка справа, свои сообщения синие.

В кабинете не было тарифа MAX, поэтому работа проверена на Telegram. Задание это допускает. Методы те же, что нужны для MAX: `CheckAccount`, `SendMessage`, `ReceiveNotification` и `DeleteNotification`.

Своего сервера нет. Браузер ходит в GREEN-API напрямую.

## Локальный запуск

Нужен Node.js 18 или новее.

```bash
npm install
npm run dev
```

Откройте http://localhost:5173

Проверка логики сообщений и номеров:

```bash
npm test
```

Сборка статики:

```bash
npm run build
npm run preview
```

## Как пользоваться

1. В [личном кабинете GREEN-API](https://console.green-api.com/) создайте инстанс MAX или Telegram и авторизуйте его QR-кодом из приложения.
2. Для входящих выберите получение через HTTP API и включите «Получать уведомления о входящих сообщениях и файлах». Поле webhook URL должно быть пустым, иначе `ReceiveNotification` вернёт ошибку. При входе приложение само включает `incomingWebhook`, если он выключен.
3. На экране входа укажите `idInstance` и `apiTokenInstance`. `apiUrl` уже заполнен адресом `https://api.green-api.com`; если в кабинете указан другой хост, вставьте его.
4. Нажмите «Новый чат» и введите номер получателя: Россия, 11 цифр с кодом 7, или Беларусь, 12 цифр с кодом 375.
5. Напишите текст и отправьте его. Ответ из мессенджера появится в этом чате.

Учётные данные и переписка хранятся в `localStorage` браузера. Кнопка «Выйти» стирает только текущий сеанс, история чатов этого инстанса остаётся на компьютере.

## Как устроен обмен с API

Создание чата: `POST /waInstance{idInstance}/checkAccount/{apiTokenInstance}`. Метод проверяет, что на номере есть аккаунт мессенджера, и возвращает постоянный `chatId`. Ответ получателя приходит уже с этим `chatId`, поэтому переписка попадает в нужный диалог. Отправка сразу на номер вида `phone@c.us` для этого не подходит.

Отправка текста: `POST /waInstance{idInstance}/sendMessage/{apiTokenInstance}` с телом `{ chatId, message }`.

Получение: цикл из двух методов HTTP API.

1. `GET /waInstance{idInstance}/receiveNotification/{apiTokenInstance}?receiveTimeout=20` ждёт одно уведомление до 20 секунд.
2. Если это входящий текст, сообщение добавляется в чат. Статусы доставки обновляют уже отправленные сообщения. Остальные уведомления пропускаются.
3. `DELETE /waInstance{idInstance}/deleteNotification/{apiTokenInstance}/{receiptId}` снимает уведомление с очереди. Пока его не удалить, следующее не придёт.

Очередь одна на инстанс и отдаёт события по порядку. Поэтому опрос запускается один раз на сеанс.
